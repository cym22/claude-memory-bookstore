# claude-memory-bookstore

[English](README.md) · **简体中文** · [繁體中文](README.zh-TW.md) · [한국어](README.ko.md) · [日本語](README.ja.md)

一套给 [Claude Code](https://claude.com/claude-code) 用的持久记忆系统,能撑到几百个文件、几百万字符,但每次会话自动加载进上下文的,始终只有很小一片。

我自己已经跑了几个月,横跨几十个长期项目。上次查的时候:**存了 250 万字符,每次会话自动读进上下文的只有 0.8%。** 这就是设计本身,不是设计里的 bug。

**六周后重新量了一次:644 万字符、921 个 markdown 文件,自动加载的索引占 0.26%。** 同口径下库大了约 2.3 倍(上面的 250 万是圆整数,首次提交当天实测 281 万)。索引本身从 1.88 万字符降到 1.68 万,比例下降主要是因为分母变大。这六周改了什么写在靠后的章节里,包括变差的那个比例。

## 这套系统解决什么问题

Claude Code 的会话上下文是有限的,但记忆库没有上限。如果你想让 AI 助手"记住一切",每次都把全部历史喂给它,结果会适得其反:它会读错重点、漏掉关键信息,速度比不用记忆系统还慢。

解法是默认少加载,并且教会系统去哪查,而不是让它记住什么。

## 三层架构

```
第 1 层 — 索引(始终加载)         占总体积 0.26%,加载频率 100%
第 2 层 — 触发词与规则(按需)     占总体积 13%,被 grep 命中时才加载
第 3 层 — 真源(按需)             占总体积 87%,被打开时才加载
```

**第 1 层 —— `MEMORY.md`。** 每条记忆只占一行:"文件存在 + 一句钩子"。它不存知识本身,只存**去哪找知识**。这是唯一一个 Claude Code 会自动读进每个新会话的文件。

**第 2 层 —— 触发词表 + 规则。** 一张手工维护的倒排索引,把"触发词"(你自然会想起来去搜的那些暗号/关键词)映射到真源文件。这个文件会长得很大(我自己那份约 85 万字符),所以纪律是:先 `grep`,再按行号读取。整份读完会被静默截断,后半部分会在你毫无察觉的情况下丢失。

**第 3 层 —— 真源。** 每个项目/主题一个文件,每次交接一份日志,每个重大拍板一份决策记录。所有结论以这里为准。上面两层都只是它的投影——一旦和第 3 层有冲突,永远第 3 层说了算。

## 读取路径:一个关键词如何找到知识

1. 你在任意会话里敲一个触发词——项目代号、事故名称,或任何你自然会想到的说法。
2. Claude 去触发词表里 grep 它(不是整份读,见上面第 2 层)。
3. 拿到一个指针 + 一句话现状:`状态 触发词A · 触发词B → 真源文件 [硬事实]`。方括号里只放 grep 命中当下就需要用到的东西:回滚命令、硬数字、结论。
4. 打开真源文件,继续工作。索引里缓存的判断不算数——只有真源文件的结论才算数。

## 写入路径:三道自动闸

**第 0 道闸 —— 备份 + 版本层**(`hooks/memory_backup.sh`,在每次 `PostToolUse` 的 `Write|Edit` 触发):把记忆目录镜像到备份位置,并在每次写入时提交到 git。如果备份盘没挂载,它会静默失败并只发一条去重后的告警,而不是无限重试——盘恢复后下一次写入会自动补齐。

**第 1 道闸 —— 存量闸**(`hooks/memory_size_gate.py`):当索引体积越过阈值,或触发词表某一天涨得太多时,通过你自己接的通知渠道提醒你。三条判据,每条每天最多触发一次,不会变成你学会无视的噪音。

**第 2 道闸 —— 流量闸**(同一个脚本里更新的部分):光有存量闸还不够。对索引膨胀做过一次成分分解后发现,**新增行 vs 旧行变胖的比例大约是 4~7:1**——也就是说,定期清理永远只是治标,第二天症状照样复发。流量闸改在写入的那一刻就拦截问题:它检查你刚刚往索引里加的这一段 diff——如果新增行太长、同一个真源被两行索引重复指向、或者加了新的事件指针却没有退休旧的——就会把这条反馈发回**当前正在写入的那个 Claude 会话**,走的是 `PostToolUse` hook 的 `hookSpecificOutput.additionalContext` 字段,而不是 `exit 2`(后者只有人看得到,进不了模型的上下文)。

## 记忆冲突时,谁说了算

两条记忆打架时,裁决顺序是:你当场给出的明确指令(永远最高)> 真源文件 > 触发词表投影 > 索引钩子行 > 旧的日志快照。同层冲突按日期新的胜。裁不出来的时候,系统会问你,而不是自己折中猜一个答案。

## 这六周改了什么

三层结构本身站住了。下面几项里有两项在第一次提交时就存在、只是没写进 README,其余是新加的。

**降层归档**(`_archive_index.md`,7 月起)。做完的项目和冷掉的线不删,只降层:索引里那行挪进这个文件,真源文件原地不动。降层的验收标准是「从 `MEMORY.md` 消失的每一条都落进了归档文件」。没有这条,降层和删除在数据上分不出来。

**项目档案**(`projects/<名>.md`,8 月底)。索引原来是流水账:每份交接单、每次审计、每个拍板各占一行,只增不减;索引里 38% 的链接指向按日期命名的 log。现在每个长期项目一份档案、自带时间线,新的 log 追加进档案而不是索引。五个项目照此归档后,索引从 24,349 字符降到 20,782,链接零丢失。

**分区索引**(`_matrix_index.md`,8 月底)。索引一个月内两次撞顶(Claude Code 读到 24,400 字符就截断)。一个项目群占了 113 条指针行里的 66 条、57% 的字符,于是整区拆成独立索引文件,主索引只留一行指过去。价值不在那一次性的降幅:此后约一半的新增行会进分区,而不是进常驻文件。

**写入通道曾经是盲区。** 仓库里的 hook 挂在 `PostToolUse` 的 `Write|Edit` 上。凡是通过 `Bash` 写的记忆——python 脚本、`sed`、重定向——备份、git 提交、体积闸一个都不触发,而这恰恰是闸最该看见的批量改动。这个盲区好几周没被发现。修法是加一个能识别记忆路径的 `Bash` matcher,再加一个定时任务兜底提交没被 commit 的改动。复制 hooks 的时候,把这条教训一起复制走。

**量体积用字符,不用字节。** `wc -c` 把索引体积误诊过不止一次,日志里记到第四次。中英混排大约 1.6 到 1.9 字节一个字符,字节数会高报六到九成,真实 1.5 万字符时就能撞上 24,400 的阈值。体积闸所有阈值都走 `len(open(path, encoding='utf-8').read())`,而且在第一次提交之前就是如此。

### 第 2 层的代价

第 2 层没守住比例。触发词表占总体积 13%,比第一次提交时的 6% 翻了一倍多,单文件 849,747 字符。

退役条目不是原因。底部「仓库 / 已沉淀」那一段只有约 1,600 字符、二十来行,每行是一个书签,回答「那事已经完了,现在看 X」。这里的退役是降级成书签而不是删掉,因为几个月后你还是会敲那个老暗号。

原因是肥卡。733 条条目,中位 741 字符;超过 2,000 字符的 111 条占了全文 49%,最肥的一条 17,604。表头自己的纪律是「一句现状 + 硬事实,细节回真源」。这条纪律 7 月手工执行过一次,把文件从 107K 压到 73K,两个月就长回来了。存量闸会在某条新条目越过 800 字符那天报一次;已经肥了还在继续长的条目什么都不触发。流量闸根本不看这个文件,它只 diff `MEMORY.md`。

触发词的命中数据我还没提取,但它是存在的:每一次对总台的 grep 都记录在会话转录里,最近一个月 190 个会话、874 次。没提取之前,分不出哪张卡在承重、哪张只是老。

在这个体积下「先 grep 再读」仍然有效。失效的是用词:拿 14 句我自然会说的话去搜,5 句零命中,全都撞在当天新写、用了系统名而不是我真会说的那句话的条目上。

(数字为 2026-09-16 实测。)

## 安装

1. 把 `hooks/memory_backup.sh` 和 `hooks/memory_size_gate.py` 复制到 `~/.claude/hooks/`,并把每个文件开头的占位路径(备份目标、通知用的 env 文件、记忆目录)改成你自己的。
2. 在 `~/.claude/settings.json` 里接上备份 hook:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path // empty' | /bin/bash $HOME/.claude/hooks/memory_backup.sh",
            "timeout": 120,
            "async": true
          }
        ]
      }
    ]
  }
}
```

3. 新建你自己的记忆目录(文件排布参考 `demo/`),开始把 `MEMORY.md` 写成一行一个钩子,具体细节放进旁边对应的 topic 文件里。
4. 如果想给备份闸/体积闸接 Telegram 告警,把 `TG_TOKEN` / `TG_CHAT_ID` 放进一个 env 文件,让 `TG_ENV` 指向它——这个文件绝不能提交进 git(已经在 `.gitignore` 里)。

## `demo/` 目录里是什么

一套完全虚构的示例文件(一个假想的"widget 发布项目"),用来展示预期的文件格式——`MEMORY.md` 索引条目、触发词表片段、一份真源 topic 文件。这个仓库里没有任何一条是真实项目、客户或账号信息;README 里的数字(644 万字符、0.26%、三层结构)来自我自己的真实使用情况,但你能浏览到的文件内容全部是占位符。
